# 데이터 아키텍처 팀 구성 가이드

데이터 아키텍처(DA) 조직의 역할·업무·권한·책임을 정의할 때 사용하는 표준 템플릿이다. 사용자가 팀을 새로 꾸리거나, 기존 조직의 R&R을 정비하거나, "이 업무는 누가 맡아야 하나"를 물을 때 이 문서를 근거로 답한다.

## 사용 시점

다음과 같은 요청에 사용한다.

- 데이터 아키텍처 팀/조직을 새로 구성하려는 경우
- 특정 데이터 업무의 담당자, 권한, 책임을 정의해야 하는 경우
- 직무기술서(Job Description)나 RACI 매트릭스를 작성하는 경우
- "표준은 누가 정하나", "DDL은 누가 실행하나"처럼 역할 경계를 묻는 경우
- 데이터 거버넌스 정책에서 의사결정권자와 실무자를 구분해야 하는 경우

## 핵심 원칙 (왜 이렇게 나누는가)

역할을 나누는 목적은 **책임의 공백과 중복을 동시에 없애기 위해서**다. 데이터는 한 사람의 실수가 전사로 전파되므로, 누가 "결정"하고 누가 "실행"하며 누가 "검증"하는지가 분리되어야 한다.

1. **결정과 실행의 분리**: 표준·모델·정책의 최종 승인은 총괄 DA가, 실행은 각 담당자가 맡는다. 같은 사람이 만들고 승인하면 견제가 사라진다.
2. **생명주기 기반 분업**: 표준 정의 → 모델 설계 → 물리 구축 → 데이터 이관 → 실시간 동기화로 이어지는 흐름의 각 단계마다 전문 담당자를 둔다.
3. **품질의 독립성**: 품질담당자는 만드는 사람과 분리되어야 객관적으로 검증할 수 있다.
4. **단일 책임자(Single Accountable)**: 모든 활동에는 최종 책임자가 정확히 1명 있어야 한다(RACI의 A).

## 역할 정의 표준 템플릿

각 역할은 **반드시 아래 4개 항목으로** 정의한다. 직무기술서를 작성할 때 이 구조를 그대로 사용한다.

```
### [역할명]
- 한 줄 정의: 이 역할이 조직에서 책임지는 단 하나의 핵심
- 주요 업무(Tasks): 실제로 수행하는 구체적 작업 목록
- 권한(Authority): 이 역할이 단독으로 결정·실행할 수 있는 범위
- 책임(Accountability): 결과가 잘못되었을 때 책임지는 범위
```

권한과 책임은 짝을 이룬다. 권한 없는 책임은 부담이고, 책임 없는 권한은 위험이다. 둘을 항상 함께 정의한다.

## 1. 총괄 DA (Chief Data Architect)

- **한 줄 정의**: 전사 데이터 아키텍처의 방향을 결정하고 모든 표준·모델·정책을 최종 승인하는 의사결정권자.
- **주요 업무**
  - 데이터 아키텍처 비전과 중장기 전략 수립
  - 데이터 표준화 정책 및 거버넌스 체계 설계·공표
  - 전사 데이터 모델과 표준의 최종 검토·승인
  - 데이터 표준화 위원회 주관 및 분쟁 조정
  - 팀원 간 업무 우선순위 조정, 자원 배분
  - 경영진 보고 및 데이터 전략 의사결정 지원
- **권한**
  - 데이터 표준·모델·정책의 최종 승인권 및 반려권
  - 표준 예외(Exception) 승인권
  - 표준 위반에 대한 시정 명령권
  - 팀 내 업무 배분 및 우선순위 결정권
- **책임**
  - 전사 데이터의 일관성과 아키텍처 무결성 확보
  - 데이터 거버넌스 정책의 실효성
  - 모든 최종 의사결정의 결과

## 2. 표준담당자 (Data Standards Steward)

- **한 줄 정의**: 표준단어·표준도메인·표준용어·표준코드를 정의하고 전사 일관성을 유지하는 표준의 관리자.
- **주요 업무**
  - 표준단어 사전 작성·관리 (단어명, 영문약어, 동의어, 금지어)
  - 표준도메인 정의·관리 (데이터 타입, 길이, 형식)
  - 표준용어 등록·관리 (단어+도메인 조합, 영문 물리명 생성)
  - 표준코드 정의·관리 (코드그룹, 코드값, 코드명)
  - 표준 준수 여부 점검 및 위반 사항 식별
  - 표준 변경 요청 검토 및 영향도 분석
  - 표준 가이드 배포 및 현업 교육
- **권한**
  - 표준 등록·수정·폐기 실행권 (총괄 DA 승인 범위 내)
  - 표준 위반 지적권 및 시정 요청권
  - 신규 표준 제안권
- **책임**
  - 표준 사전의 정확성과 최신성 유지
  - 표준 간 충돌·중복 방지
  - 표준 적용의 전사 일관성

## 3. 데이터 모델러 (Data Modeler)

- **한 줄 정의**: 개념·논리·물리 데이터 모델을 설계하고 표준을 모델에 반영하는 설계자.
- **주요 업무**
  - 개념 모델(ERD) 설계: 핵심 엔터티와 관계 도출
  - 논리 모델 설계 및 정규화 (1NF→2NF→3NF)
  - 물리 모델 설계: 테이블·컬럼·키 구조 확정
  - 엔터티/속성/관계/식별자 정의
  - 표준용어 기반 컬럼명 적용
  - 모델 변경 관리 및 버전 이력 유지
  - 모델 문서화 및 메타데이터 등록
- **권한**
  - 모델 설계·수정 실행권
  - 엔터티·속성·관계 정의권
  - 표준담당자에 대한 신규 표준 적용 요청권
- **책임**
  - 모델의 정합성·완전성·정규화 수준
  - 모델의 표준 준수
  - 논리 모델과 물리 DB의 일치성

## 4. 품질담당자 (Data Quality Manager)

- **한 줄 정의**: 데이터 품질 기준을 정의하고 측정·모니터링·개선을 주도하는 품질의 검증자.
- **주요 업무**
  - 데이터 품질 기준 정의 (완전성·유효성·일관성·정확성·유일성)
  - 품질 진단 규칙(룰) 작성 및 적용
  - 정기 품질 측정 및 모니터링
  - 오류 데이터 식별 및 정제 계획 수립
  - 품질 지표(KPI) 관리 및 경영진 보고
  - 품질 개선 활동 추진 및 효과 검증
- **권한**
  - 품질 진단 실행권 및 품질 기준 설정권
  - 오류 데이터에 대한 시정 요청권
  - 품질 미달 데이터의 사용 보류 권고권
- **책임**
  - 전사 데이터 품질 수준의 유지·향상
  - 품질 지표의 정확성과 신뢰성
  - 품질 이슈의 추적과 종결

## 5. 마이그레이션담당자 (Data Migration Manager)

- **한 줄 정의**: 기존 시스템 데이터를 신규 시스템으로 정확하게 이관하는 데이터 이동의 책임자.
- **주요 업무**
  - 마이그레이션 전략·계획·일정 수립
  - 원천-목표 매핑(Source-Target Mapping) 정의
  - ETL/이관 스크립트 개발
  - 데이터 정제·변환·검증 규칙 적용
  - 이관 리허설(시험 이관) 및 검증
  - 본 이관 실행 및 건수·정합성 검증
  - 롤백 계획 수립 및 실패 대응
- **권한**
  - 마이그레이션 실행권
  - 데이터 변환·매핑 규칙 정의권
  - 이관 일정 조정권
- **책임**
  - 이관 데이터의 정확성·완전성
  - 데이터 손실 및 누락 방지
  - 이관 후 원천-목표 정합성 검증 결과

## 6. 물리DB구축담당자 (Physical Database Engineer / DBA)

- **한 줄 정의**: 물리 모델을 실제 DBMS에 구축하고 성능·가용성을 책임지는 운영의 담당자.
- **주요 업무**
  - DDL 스크립트 작성 및 실행 (CREATE/ALTER)
  - 테이블·인덱스·파티션·제약조건 생성
  - 데이터 타입 및 무결성 제약 구현
  - 성능 튜닝 (인덱스 설계, 쿼리 최적화)
  - 백업·복구 체계 구축 및 운영
  - DB 접근 권한(계정) 관리
  - 용량·자원 모니터링
- **권한**
  - DDL 실행권 (DB 객체 생성·변경·삭제)
  - DB 접근 권한 부여·회수권
  - 성능 최적화 조치 실행권
- **책임**
  - DB의 가용성·안정성·성능
  - 데이터 보안 및 백업·복구 가능성
  - 물리 구조와 물리 모델의 일치

## 7. CDC담당자 (Change Data Capture Manager)

- **한 줄 정의**: 데이터 변경을 실시간으로 감지·전파하여 시스템 간 데이터 일관성을 유지하는 실시간 동기화 담당자.
- **주요 업무**
  - CDC 아키텍처 설계 (로그 기반/트리거 기반 방식 선정)
  - CDC 솔루션 구축·운영 (예: Debezium, GoldenGate, Kafka Connect)
  - 변경 데이터 캡처 대상·규칙 정의
  - 실시간 동기화 파이프라인 구축
  - CDC 모니터링, 지연(Latency) 관리, 장애 대응
  - 원천-목표 간 데이터 일관성 검증
- **권한**
  - CDC 파이프라인 구축·운영권
  - 동기화 대상·규칙 정의권
  - 트랜잭션 로그 접근권
- **책임**
  - 실시간 동기화의 정확성과 적시성
  - 동기화 구간의 데이터 일관성 보장
  - CDC 시스템의 가용성

## RACI 책임 매트릭스

역할 경계가 모호할 때 **반드시 이 표를 기준으로** 판단한다. 각 행(활동)에는 A가 정확히 1명이다.

| 활동 | 총괄 DA | 표준담당자 | 모델러 | 품질담당자 | 마이그레이션 | 물리DB구축 | CDC담당자 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 데이터 표준 정책 수립 | **A** | R | C | C | I | I | I |
| 표준단어·도메인·용어·코드 정의 | **A** | R | C | I | I | I | I |
| 개념·논리 모델 설계 | **A** | C | R | C | I | I | I |
| 물리 모델 설계 | **A** | C | R | I | I | C | I |
| 물리 DB 구축(DDL) | **A** | I | C | I | I | R | C |
| 데이터 품질 기준·진단 | **A** | C | C | R | C | I | I |
| 데이터 마이그레이션 | **A** | C | C | C | R | C | I |
| 실시간 동기화(CDC) | **A** | I | C | C | I | C | R |
| 표준 준수 점검 | **A** | R | I | C | I | I | I |
| 변경 요청 승인 | **A/R** | C | C | C | C | C | C |

**RACI 범례**
- **R (Responsible / 실무수행)**: 실제로 작업을 수행하는 역할
- **A (Accountable / 최종책임)**: 결과에 최종 책임을 지는 역할 (활동당 1명)
- **C (Consulted / 협의)**: 작업 전 의견을 구해야 하는 역할 (양방향 소통)
- **I (Informed / 통보)**: 결과를 통보받는 역할 (단방향 소통)

## 협업 워크플로우 (데이터 생명주기)

역할들은 아래 순서로 맞물려 일한다. 앞 단계의 산출물이 뒷 단계의 입력이 된다.

1. **표준 정의** — 표준담당자가 표준단어/도메인/용어/코드를 정의하고 총괄 DA가 승인한다.
2. **모델 설계** — 데이터 모델러가 승인된 표준을 사용해 개념→논리→물리 모델을 설계한다.
3. **물리 구축** — 물리DB구축담당자가 물리 모델을 DDL로 변환해 실제 DB를 생성한다.
4. **데이터 이관** — 마이그레이션담당자가 기존 데이터를 신규 구조로 옮기고 검증한다.
5. **품질 검증** — 품질담당자가 전 단계에 걸쳐 품질을 측정하고 오류를 시정 요청한다.
6. **실시간 동기화** — CDC담당자가 운영 중 발생하는 변경을 실시간으로 전파한다.
7. **거버넌스 순환** — 변경 요청은 총괄 DA 승인을 거쳐 1단계로 환류한다.

**경계가 자주 헷갈리는 지점**
- *물리 모델 설계 vs 물리 DB 구축*: 모델러가 "설계"하고, 물리DB담당자가 "실행(DDL)"한다.
- *마이그레이션 vs CDC*: 마이그레이션은 일회성 대량 이관, CDC는 운영 중 지속적 실시간 동기화다.
- *표준 준수 점검 vs 품질 진단*: 표준담당자는 "표준 위반"을, 품질담당자는 "데이터 값의 오류"를 본다.

## 권한 등급 체계

권한이 충돌할 때 적용하는 등급이다. 상위 등급이 하위 등급의 결정을 반려할 수 있다.

| 등급 | 권한 | 보유 역할 |
|------|------|-----------|
| L1 최종 승인 | 표준·모델·정책 확정, 예외 승인, 시정 명령 | 총괄 DA |
| L2 정의·설계 | 표준/모델/품질기준/이관규칙의 작성·변경 | 표준담당자, 모델러, 품질담당자, 마이그레이션 |
| L3 운영·실행 | DB 객체 생성, 권한 부여, 파이프라인 운영 | 물리DB구축, CDC담당자 |

운영 권한(L3)은 정의 권한(L2)과 분리한다. 설계하는 사람과 실제 DB를 바꾸는 사람을 나누면, 검토되지 않은 변경이 운영에 반영되는 사고를 막을 수 있다.

## 직무기술서 작성 체크리스트

각 역할을 정의할 때 아래를 모두 채웠는지 확인한다.

- [ ] 한 줄 정의가 "이 역할이 없으면 무엇이 안 되는가"에 답하는가
- [ ] 주요 업무가 추상적 구호가 아니라 구체적 작업으로 적혔는가
- [ ] 권한과 책임이 1:1로 짝을 이루는가 (권한 없는 책임/책임 없는 권한이 없는가)
- [ ] RACI에서 이 역할이 A인 활동이 명확한가
- [ ] 인접 역할과의 경계(누가 어디까지)가 정의되었는가
- [ ] 소규모 조직이라면 어떤 역할을 겸임할지 명시했는가 (예: 모델러+표준담당자, 물리DB+CDC)

## 소규모 팀 적용 가이드

7개 역할을 모두 별도 인원으로 둘 수 없는 경우, 아래 겸임 조합을 권장한다. 단, **품질담당자는 가능한 한 독립**시켜 검증의 객관성을 유지한다.

- 3~4인 팀: 총괄 DA / (표준+모델러) / (물리DB+CDC) / 품질
