# 데이터 모델링 3단계 (Data Modeling 3 Stages)

## 개요

데이터 모델링은 현실 세계의 업무 요구사항을 데이터베이스로 구현하기까지 **3단계**를 거칩니다.
각 단계는 추상 수준이 다르며, 순서대로 진행됩니다.

---

## 1단계 — 개념적 모델링 (Conceptual Modeling)

### 목적
현실 세계의 업무 요구사항을 비전문가도 이해할 수 있는 수준으로 추상화합니다.
기술적 구현은 전혀 고려하지 않고, "어떤 정보가 필요한가?"에만 집중합니다.

### 핵심 산출물
- ERD (개체-관계 다이어그램, Entity-Relationship Diagram)

### 주요 구성 요소

| 요소 | 설명 | 예시 |
|------|------|------|
| 개체 (Entity) | 관리할 대상 | 학생, 강좌, 교수 |
| 속성 (Attribute) | 각 개체가 가진 정보 | 학번, 이름, 전화번호 |
| 관계 (Relationship) | 개체 간의 연관성 | 학생이 강좌를 *수강하다* |

### 특징
- DBMS 종속성 없음
- 비전문가(업무 담당자)도 검토 가능
- 카디널리티(1:1, 1:N, M:N) 표현

---

## 2단계 — 논리적 모델링 (Logical Modeling)

### 목적
개념 모델을 DBMS에 독립적인 논리 구조로 정제합니다.
"어떻게 데이터를 구조화할 것인가?"를 결정하는 단계입니다.

### 핵심 산출물
- 릴레이션(테이블) 스키마
- 기본키(PK), 외래키(FK) 정의

### 주요 작업

| 작업 | 설명 |
|------|------|
| 정규화 (Normalization) | 중복 제거 및 이상 현상 방지 (1NF → 2NF → 3NF) |
| 기본키 (Primary Key) | 각 행을 고유하게 식별하는 컬럼 |
| 외래키 (Foreign Key) | 테이블 간의 관계를 표현하는 컬럼 |

### 정규화 단계
- **1NF**: 원자값(더 이상 분리 불가한 값)으로 구성
- **2NF**: 부분 함수 종속 제거
- **3NF**: 이행 함수 종속 제거

### 특징
- DBMS 종속성 없음
- 설계자와 개발자가 주로 검토
- 관계형 모델 기반

---

## 3단계 — 물리적 모델링 (Physical Modeling)

### 목적
논리 모델을 특정 DBMS(MySQL, Oracle, PostgreSQL 등)에 실제로 구현합니다.
성능과 저장 효율을 최우선으로 고려합니다.

### 핵심 산출물
- DDL(CREATE TABLE) SQL 스크립트
- 인덱스, 파티션 설계서

### 주요 작업

| 작업 | 설명 | 예시 |
|------|------|------|
| 데이터 타입 결정 | 컬럼별 저장 타입 지정 | `VARCHAR(50)`, `INT`, `DATE` |
| 인덱스 (Index) | 조회 성능 최적화 | 자주 검색하는 컬럼에 인덱스 추가 |
| 파티셔닝 | 대용량 데이터 분산 처리 | 날짜별 테이블 분리 |
| 반정규화 | 성능을 위해 일부 중복 허용 | 조인 횟수 줄이기 위한 컬럼 복제 |

### 특징
- DBMS 종속적 (MySQL, Oracle 등 문법 차이 존재)
- DBA·개발자가 담당
- 실제 운영 환경의 성능을 고려한 설계

---

## 3단계 비교 요약

| 항목 | 개념적 모델링 | 논리적 모델링 | 물리적 모델링 |
|------|--------------|--------------|--------------|
| 관심사 | 업무 요구사항 | 논리 구조 | 성능·구현 |
| 대상 | 비전문가 포함 | 설계자 | DBA·개발자 |
| DBMS 종속 | 없음 | 없음 | 있음 |
| 주요 도구 | ERD | 정규화, 스키마 | SQL DDL, Index |
| 산출물 | 개체-관계 다이어그램 | 테이블 스키마 | CREATE TABLE SQL |

---

## 흐름 요약

```
현실 세계 요구사항
       ↓
[1단계] 개념적 모델링 → ERD 작성
       ↓ (정제·구조화)
[2단계] 논리적 모델링 → 테이블 스키마 + 정규화
       ↓ (DBMS 선택·최적화)
[3단계] 물리적 모델링 → DDL SQL + 인덱스 + 파티션
       ↓
실제 데이터베이스 구현
```
