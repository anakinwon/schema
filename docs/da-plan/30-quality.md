# 30. 데이터 품질 감리 담당자 업무계획

## ① 역할 정의

> **데이터 품질 감리 담당자**: 10-표준 및 20-모델링 팀의 산출물이 표준화 지침, 명명 규칙, 정규화 원칙, 무결성 제약 기준을 준수하는지 독립적 관점에서 검수하고, 미준수 항목에 대해 시정 요구 및 추적·관리하는 사람이다.

| 역할 영역 | 구체적 책임 |
|-----------|-------------|
| 표준준수 감리 | STD_DIC(STANDARD_YN/FORBID_YN), STD_DOM, STD_CODE 기준 준수 여부 점검 |
| 명명규칙 감리 | 주제영역·엔터티·속성·컬럼의 명명 규칙 준수 여부 점검 |
| 정규화 감리 | 1NF/2NF/3NF 이상 준수 여부, 반정규화 사유 적정성 점검 |
| 무결성 감리 | PK/FK/NULL/DEFAULT 제약 완전성 및 참조무결성(RI) 점검 |
| 결과 관리 | 시정조치 요구, 조치 결과 추적, DA 리더 보고 |

### 2-2. SQLite 메타 DB(DA#5) 스키마 — 품질 감리 기준 도출

#### STD_DIC (표준단어사전) — 표준준수 감리 기준

| 컬럼 | 타입 | 감리 활용 |
|------|------|-----------|
| `STANDARD_YN` | VARCHAR2(1) | 비표준어 사용 여부 검사 — 'N'인 단어 사용 시 비표준 판정 |
| `FORBID_YN` | VARCHAR2(1) | 금칙어 사용 여부 검사 — 'Y'인 단어 사용 시 즉각 반려 |
| `DIC_GBN_CD` | VARCHAR2(4) | 단어 구분(명사형 여부) 확인 |
| `USE_END_DT` | VARCHAR2(14) | 폐기된 단어 사용 여부 검사 |
| `AVAL_ST_DT` / `AVAL_END_DT` | VARCHAR2(14) | 유효기간 내 사용 여부 |

#### STD_DOM (표준도메인) — 도메인 정합성 감리 기준

| 컬럼 | 타입 | 감리 활용 |
|------|------|-----------|
| `DATA_TYPE_CD` | VARCHAR2(16) | 속성-도메인 데이터타입 불일치 검사 |
| `DATA_LEN` | NUMBER | 속성-도메인 길이 초과 검사 |
| `DATA_SCALE` | NUMBER | 소수점 자리수 불일치 검사 |
| `DATA_MIN` / `DATA_MAX` | VARCHAR2(40) | 값 범위 초과 여부 검사 |
| `DATA_FORMAT` | VARCHAR2(4000) | 날짜·패턴 형식 준수 검사 |
| `PRIVACY_ACT` | NUMBER | 개인정보보호법 대상 속성 처리 여부 |
| `SECURITY_YN` / `SECURITY_LEVEL` | CHAR(1) / VARCHAR2(50) | 보안등급 적정 적용 여부 |

#### STD_AREA (주제영역) — 표준 적용 범위 감리

| 컬럼 | 타입 | 감리 활용 |
|------|------|-----------|
| `TERM_USE_YN` | VARCHAR2(4) | 해당 주제영역의 표준용어 사용 의무 여부 |
| `DOM_USE_YN` | VARCHAR2(4) | 표준도메인 사용 의무 여부 |
| `CODE_USE_YN` | VARCHAR2(4) | 표준코드 사용 의무 여부 |

#### STD_CODE (표준코드) — 코드 표준 준수 감리

| 컬럼 | 타입 | 감리 활용 |
|------|------|-----------|
| `CD_GBN_CD` | TEXT | 코드 분류 체계 준수 여부 |
| `DOM_ID` | TEXT | 코드-도메인 연결 적정성 |
| `CD_LEN` | NUM | 코드값 길이 표준 준수 |

#### DA_TERM (용어사전) — 표준용어 적용 감리

| 컬럼 | 타입 | 감리 활용 |
|------|------|-----------|
| `TERM_NM` | VARCHAR2(4000) | 속성명이 표준용어와 일치하는지 검사 |
| `TERM_GBN_CD` | VARCHAR2(4) | 용어 구분 코드 적정성 |
| `TERM_ABBR` | VARCHAR2(200) | 약어 사용 시 표준 약어 사용 여부 |

### Phase 1: 표준준수 감리 계획

**감리 범위**: 10-표준 팀이 등록한 STD_DIC, STD_DOM, STD_CODE, DA_TERM 데이터 및 20-모델링 팀 산출물의 표준 준수 여부

#### 1-1. STD_DIC 기반 비표준어·금칙어 점검

| 점검항목 | 판정 기준 | 점검 방법 | 비고 |
|----------|-----------|-----------|------|
| 비표준어 사용 여부 | `STANDARD_YN = 'N'`인 단어를 엔터티/속성명에 사용하면 Fail | `SELECT * FROM STD_DIC WHERE STANDARD_YN='N'` 결과와 모델 비교 | DQ시스템 "데이터 프로파일링" 기능 활용 |
| 금칙어 사용 여부 | `FORBID_YN = 'Y'`인 단어 사용 시 즉각 반려(Hard Fail) | `SELECT * FROM STD_DIC WHERE FORBID_YN='Y'` 결과와 모델 비교 | 금칙어 목록(`.claude/skills/data-architecture/10-standard/da-std-dictionary-mgmt/references/금칙어_목록.md`) 함께 확인 |
| 폐기 단어 사용 여부 | `USE_END_DT IS NOT NULL` AND `USE_END_DT <= 현재일자` | 유효기간 만료 단어 목록 추출 후 모델 대조 | |
| 이음동의어 중복 여부 | `STD_DIC_REL` 테이블에서 동의어 매핑 미등록 단어 확인 | `STD_DIC_REL` JOIN 조회 | 지침서 3.3절 — "이음동의어는 허용하지 않는다" |

#### 1-2. 도메인 정합성 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 속성-도메인 데이터타입 불일치 | 모델의 속성 데이터타입이 `STD_DOM.DATA_TYPE_CD`와 상이하면 Warning | `STD_DOM` 조회 후 모델 속성과 비교 |
| 속성 길이 표준 초과 | `DATA_LEN` 초과 시 Warning | 모델 DDL과 `STD_DOM.DATA_LEN` 비교 |
| 날짜·패턴 형식 불일치 | `DATA_FORMAT` 미준수 시 Warning | DQ시스템 "날짜/패턴/코드 분석" 기능 |
| 개인정보·보안 속성 미표시 | `PRIVACY_ACT=1` 또는 `SECURITY_YN='Y'`인 도메인의 보안 처리 누락 | `STD_DOM WHERE PRIVACY_ACT=1 OR SECURITY_YN='Y'` |

#### 1-3. 표준코드 준수 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 코드-도메인 연결 누락 | `STD_CODE.DOM_ID IS NULL` 이면서 도메인 연결이 필요한 코드 | `STD_CODE WHERE DOM_ID IS NULL` |
| 비표준 코드값 사용 | 모델의 코드 속성에 `STD_CODE`에 미등록된 값 사용 | DQ시스템 "업무 규칙(BR) 분석" 기능으로 SQL 검증 |

**산출물**: 표준준수 감리 체크리스트 (엑셀/마크다운), 비표준·금칙어 발견 목록, 도메인 불일치 목록

### Phase 2: 명명규칙 감리 계획

**감리 범위**: 20-모델링 팀의 논리/물리 모델 산출물(엔터티명, 테이블명, 속성명, 컬럼명)

#### 2-1. 주제영역 명명규칙 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 주제영역명 표준화 | `STD_AREA.STD_AREA_NM`에 등록된 명칭과 일치 여부 | STD_AREA 목록과 모델 대조 |
| 상위영역 계층 구조 | `UP_STD_AREA_ID` 참조 무결성 및 깊이 적정성 | `STD_AREA` 계층 쿼리 |
| 영역별 표준 적용 의무 준수 | `TERM_USE_YN`, `DOM_USE_YN`, `CODE_USE_YN`이 'Y'인 영역의 의무 적용 | 주제영역별 의무 항목 체크 |

#### 2-2. 엔터티/테이블 명명규칙 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 논리명 명사형 여부 | `STD_DIC.ENT_CLSS_YN = 'Y'`인 단어 조합으로 구성됐는지 | STD_DIC 단어 분해 분석 |
| 물리명 약어 표준 준수 | `STD_DIC.DIC_PHY_NM` 또는 `DIC_PHY_FLL_NM` 사용 여부 | 모델 물리명과 STD_DIC 비교 |
| 복수형 사용 금지 | 테이블명에 복수형 영문 사용 여부 | 정규식 패턴 검사 `[A-Z]+S\b` |

#### 2-3. 속성/컬럼 명명규칙 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 표준용어 적용 여부 | 속성 논리명이 `DA_TERM.TERM_NM`에 등록된 표준용어인지 | `DA_TERM WHERE TERM_GBN_CD='ATTR'` 대조 |
| 속성명 단어 조합 규칙 | `STD_WORD_COMBI` 테이블의 허용 조합 준수 여부 | `STD_WORD_COMBI` 쿼리 |
| 약어 표준 준수 | 컬럼명 약어가 `DA_TERM.TERM_ABBR` 또는 `STD_DIC.DIC_PHY_NM`과 일치 | 물리명 약어 목록 비교 |
| 접두어/접미어 규칙 | ID, CD, NM, DT, YN 등 표준 접미어 사용 여부 | 정규식 + STD_DIC 분류 코드 대조 |

**산출물**: 명명규칙 감리 체크리스트, 미준수 엔터티/속성 목록 (논리명·물리명·위반 사유)

### Phase 3: 정규화 감리 계획

**감리 범위**: 20-모델링 팀의 논리 데이터 모델(ERD)

#### 3-1. 1정규형(1NF) 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 반복 그룹 속성 존재 여부 | 배열·목록형 속성이 단일 속성으로 정의되어 있는지 | ERD 수동 검토 + DQ프로파일링 "컬럼분석" |
| 복합 속성 분해 여부 | 하나의 속성에 여러 값이 ','로 저장되는 패턴 | DQ시스템 "날짜/패턴/코드 분석" |
| 기본키 존재 여부 | 모든 엔터티에 PK가 정의되어 있는지 | ERD DDL 검토 |

#### 3-2. 2정규형(2NF) 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 부분 함수적 종속 여부 | 복합 PK에서 일부 키에만 종속된 속성 존재 여부 | ERD 수동 분석, FD(함수적 종속) 다이어그램 작성 |
| 복합 PK 엔터티 집중 검토 | 복합 PK를 가진 엔터티 목록 추출 후 전수 점검 | DDL에서 복합 PK 엔터티 추출 |

#### 3-3. 3정규형(3NF) 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 이행적 종속 여부 | 비키 속성이 다른 비키 속성에 종속되는 케이스 | ERD 수동 분석 |
| 코드 테이블 분리 여부 | 반복적으로 사용되는 코드값이 별도 엔터티로 분리됐는지 | STD_CODE 목록과 모델 비교 |

#### 3-4. 반정규화 타당성 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 반정규화 사유 문서화 | 반정규화 적용 속성에 대한 성능 근거 존재 여부 | 모델 검토서 수동 확인 |
| DA 리더 승인 여부 | 반정규화 항목에 대한 공식 승인 이력 | 승인 워크플로우 이력 확인 |

**산출물**: 정규화 감리 체크리스트, 정규화 위반 목록 (엔터티명·속성명·위반 유형·시정 방안)

### Phase 4: 무결성 감리 계획

**감리 범위**: 20-모델링 팀의 물리 데이터 모델(DDL) 및 논리 모델의 관계 정의

#### 4-1. PK 완전성 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| PK 정의 누락 | 모든 테이블에 PRIMARY KEY가 정의되어 있는지 | DDL 파싱 + DQ시스템 "컬럼분석" PK 분석 |
| PK 컬럼 NULL 허용 여부 | PK 컬럼에 NOT NULL 제약 적용 여부 | DDL 검토 |
| PK 유일성 보장 | 자연키 사용 시 도메인 중복 위험성 평가 | `STD_DOM.DATA_ENUM`, `DATA_MIN/MAX` 검토 |

#### 4-2. FK 완전성 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 참조무결성(RI) 정의 여부 | ERD의 관계선이 DDL FK 제약으로 구현됐는지 | DQ시스템 "관계분석: 참조무결성(RI) 검증" |
| 고아 레코드 위험성 | FK ON DELETE/UPDATE 정책 정의 여부 | DDL 검토 |
| 순환 참조 여부 | 두 테이블 간 상호 FK 참조 여부 | `STD_DOM` 연관 관계 그래프 분석 |

#### 4-3. NULL/DEFAULT 제약 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| 필수 속성 NOT NULL 정의 | 업무 필수 속성에 NOT NULL 제약이 적용됐는지 | `STD_DOM.DATA_DEFAULT` 미정의 + NULL 허용 속성 교차 확인 |
| DEFAULT 값 표준 준수 | `STD_DOM.DATA_DEFAULT`에 정의된 기본값 사용 여부 | DDL DEFAULT 값과 STD_DOM 비교 |
| YN 플래그 DEFAULT | 'Y'/'N' 타입 속성의 DEFAULT 'N' 또는 'Y' 정의 여부 | `STD_DIC`에서 `DIC_GBN_CD`가 YN 유형인 속성 추출 |

#### 4-4. 데이터 타입 제약 점검

| 점검항목 | 판정 기준 | 점검 방법 |
|----------|-----------|-----------|
| DBMS별 타입 매핑 적정성 | `STD_DATATYPE_CONV` 테이블의 DBMS별 변환 규칙 준수 여부 | `STD_DATATYPE_CONV` 조회 후 DDL 대조 |
| CHECK 제약 정의 여부 | 코드형 속성에 `STD_CODE` 값 범위 기반 CHECK 제약 | DDL CHECK + STD_CODE 비교 |

**산출물**: 무결성 감리 체크리스트, PK/FK/NULL 위반 목록, RI 미구현 관계 목록

### Phase 5: 감리 결과 보고 및 시정조치 추적

| 단계 | 점검항목 | 도구/방법 | 산출물 | 선행조건 |
|------|----------|-----------|--------|----------|
| 5-1. 감리 결과 종합 | 4대 영역 결과 집계, Pass/Warning/Fail 통계 | 체크리스트 집계 | 감리 결과 보고서 초안 | Phase 1~4 완료 |
| 5-2. 시정조치 요구서 발행 | Fail 항목에 대한 시정 요구, 기한 설정 | 시정조치 추적 대장 | 시정조치 요구서 | 감리 결과 확정 |
| 5-3. 시정결과 확인 | 20-모델링 팀의 시정 완료 여부 재검수 | 재감리 체크리스트 | 시정 확인서 | 20-모델링 팀 시정 완료 |
| 5-4. 최종 보고 | DA 리더에게 감리 완료 보고 | 보고 회의 | 최종 감리 결과 보고서 | 5-3 완료 |
| 5-5. 이관 전 최종 확인 | 40-이관 팀 이관 착수 전 품질 확인서 발행 | 최종 체크리스트 | 이관 전 품질 확인서 | Phase 5-4 완료 |

#### 감리 결과 판정 기준

| 판정 등급 | 기준 | 조치 |
|-----------|------|------|
| **Pass** | 표준 완전 준수 | 이관 착수 가능 |
| **Warning** | 경미한 위반 (권고 수준) | 차기 스프린트 내 자율 시정 |
| **Fail** | 표준 미준수, 무결성 결함 | 시정조치 요구서 발행, 재감리 필수 |
| **Hard Fail** | 금칙어 사용, PK 누락 등 심각한 위반 | 즉각 반려, 긴급 시정 |

## ④ 타 팀원과의 인터페이스

| 협업 대상 | 인터페이스 내용 | 방향 | 시점 |
|-----------|----------------|------|------|
| **00-리더** | 감리 기준서 승인 요청 → 승인 수령 | 양방향 | Phase 0 |
| **00-리더** | 감리 결과 최종 보고 | 30-품질 → 00-리더 | Phase 5 |
| **10-표준** | STD_DIC(STANDARD_YN, FORBID_YN), STD_DOM, STD_CODE 기준 제공 요청 | 30-품질 → 10-표준 | Phase 1 착수 전 |
| **10-표준** | 금칙어 목록, 표준 도메인 목록 최신본 수령 | 10-표준 → 30-품질 | Phase 1 착수 전 |
| **20-모델링** | 논리/물리 모델 산출물 수검 요청 | 20-모델링 → 30-품질 | Phase 1~4 |
| **20-모델링** | 시정조치 요구서 발행 | 30-품질 → 20-모델링 | Phase 5-2 |
| **20-모델링** | 시정 완료 후 재감리 결과 통보 | 30-품질 → 20-모델링 | Phase 5-3 |
| **40-이관** | 이관 착수 전 품질 확인서 발행 | 30-품질 → 40-이관 | Phase 5-5 |

### 감리 프로세스 흐름

```
10-표준 (STD_DIC, STD_DOM, STD_CODE, DA_TERM 제공)
    ↓
30-품질 (감리 기준서 수립)
    ↓
20-모델링 (모델 산출물 제출)
    ↓
30-품질 (4대 감리 영역 점검)
    ↓
시정조치 요구서 → 20-모델링 (시정)
    ↓
30-품질 (재감리 → 확인서 발행)
    ↓
00-리더 (최종 보고 수신 → 이관 착수 승인)
    ↓
40-이관 (이관 착수)
```
