# 20. 데이터 모델러 업무계획

## ① 역할 정의

**데이터 모델러**는 업무 요건을 토대로 데이터 모델링을 수행하는 사람으로,  
데이터 표준화 지침을 준수해야 하는 의무를 가지며,  
표준화 지침서에 따라 속성명을 정의하고 표준 용어를 신청하는 역할을 수행한다.

주요 책임:
- 업무 요건 분석 → 논리/물리 데이터 모델 설계
- 엔터티·관계·속성 명명 시 명명규칙 지침서 준수
- 속성명 정의 후 표준 단어사전(STD_DIC) 및 표준도메인(STD_DOM) 기반으로 표준 용어 신청
- DA샵 연동을 위한 CSV import 파일 생성

---

## ② 참고한 지침서 및 근거

### 가. 주제영역 명명규칙 (`명명규칙-주제영역.pptx`)

> *"주제 영역 명은 업무를 설명하는 단수형 명사를 사용한다. 주제 영역 명은 시스템 명과 동일할 수 있으며, 엔터티 명과 같을 수 있다."*

> *"주제 영역 단계는 2 레벨을 넘어가지 않도록 정의한다."*

**명명 구조:**  
`시스템명 + _ + 1레벨 주제영역명 / 2레벨 주제영역명`

| 구분 | 설명 | 예시 |
|---|---|---|
| ① 시스템명 | 업무계(C), ODS(O), DW(D) 중 1자리 | C, O, D |
| ③ 1레벨 주제영역명 | 주제 영역의 상위 분류명 | 고객(CS), 계약(AR) |
| ⑤ 2레벨 주제영역명 | 1레벨 하위 분류명 | 기본(I), 신용(C), 조건(C) |

**영문 약어 조합 규칙:**  
`시스템 영문(1자리) + 1레벨 주제영역 영문(2자리) + 2레벨 주제영역 영문(1자리)` → 4자리

예) `업무계 C` + `고객 CS` + `기본 I` → `CCSI` / `DW D` + `계약 AR` + `조건 C` → `DARC`

**SQLite 메타 근거 (STD_AREA):**  
`STD_AREA` 테이블의 `UP_STD_AREA_ID`(상위 주제영역 ID) 컬럼이 2레벨 계층 구조를 뒷받침하며,  
`STD_AREA_NM`이 논리명, `AVAL_ST_DT`/`AVAL_END_DT`로 유효기간 관리가 이루어진다.

### 나. 엔터티 명명규칙 (`명명규칙-엔터티.pptx`)

> *"엔터티 명은 주제 영역을 포함하면서 엔터티의 정의를 나타내도록 명료하게 정의한다."*

**명명 구조:**  
`[사용용도(선택)] + 주제영역명 _ 엔터티정의 + [데이터성격(선택)]`

| 구분 | 설명 |
|---|---|
| ① 사용용도 (선택) | `[참조]`, `[복제]`, `[삭제]`, `[분석중]` 등 |
| ② 주제영역명 | `1레벨주제영역명/2레벨주제영역명` |
| ③ 구분자 | 주제영역과 엔터티를 구분하는 `_` |
| ④ 엔터티정의 | 주체·대상·행위의 명사형 단어 조합 |
| ⑤ 데이터성격 (선택) | `이력`, `집계`, `백업`, `복제`, `인터페이스`, `채번`, `코드` 등 |

**엔터티 정의 규칙:**

- **행위 엔터티:** `주체(~이) + 대상(~를) + 행위(~한)`  
  예) '상품'을 '주문'한 → `상품주문` / '고객'이 '대출'을 '승인'한 → `고객대출승인`

- **실체/기준 엔터티:** `주체(~이) + 대상(명사) + 행위(~한)`  
  예) '고객' → `고객` / '고객'이 '수신'하는 '계좌' → `고객수신계좌`

- **집계 엔터티:** `집계기준 + 집계대상 + 접미어 '집계'`  
  예) '월별' '고객'의 '주문' 집계 → `월별고객주문집계`

- **이력 엔터티:** 원천 엔터티 속성이 변경될 때 이전 데이터 관리 목적  
  예) `고객등급이력`

**예시:**

| 엔터티명 | 설명 |
|---|---|
| `고객/기본_고객` | 고객 기본 정보 |
| `고객/기본_고객등급이력` | 고객 등급 변경 이력 |
| `고객/기본_주문집계` | 주문 집계 데이터 |
| `[참조] 고객/기본_고객` | 타 주제영역에서 고객 엔터티 참조 |

### 다. 속성 명명규칙 (`명명규칙-속성.pptx`)

> *"표준 용어는 최소한 두 개 이상의 표준 단어의 조합으로 사용 (속성 도메인 등 예외 존재)"*

> *"표준 단어와 표준 도메인이 조합돼 '수식어(표준 단어) + 도메인(표준 도메인)' 형태로 구성"*

**명명 구조:**  
`주체(~이) + 대상(~를) + 행위(~한) + 도메인(기본도메인 or 속성도메인)`

| 구분 | 설명 | 예시 단어 |
|---|---|---|
| 주체 | `~이`, `~가`로 의미가 통하는 단어 | 고객, 부서, 회사 |
| 대상 | `~을`, `~를`로 의미가 통하는 단어 | 상품, 신용카드, 계좌, 대출 |
| 행위 | `~한`을 붙여 의미가 통하는 단어 | 주문, 사용, 거래, 매입 |
| 도메인 | 기본 도메인 또는 속성 도메인 | 금액, 번호, 명, 수, 율, 날짜, 여부, 코드 |

**도메인 그룹별 표준 용어 예시:**

| 도메인 그룹 | 예시 |
|---|---|
| 번호 | `고객연체대출번호` |
| 명 | `주문고객명` |
| 수 | `주문상품수` |
| 율 | `계약펀드율` |
| 금액 | `고객주문금액`, `대출연체금액` |
| 날짜 | `대출연체일자`, `고객상품반품일시` |
| 내용 | `배송요청내용` |
| 여부 | `법인고객여부`, `계좌삭제여부` |
| 코드 | `고객유형코드`, `고객등급종류코드`, `개인법인구분코드` |

**코드 속성 명명 규칙:**  
`주체(~의) + 대상(~에 대한) + 목적(~을) + 구분자(구분한) + 코드`

- **구분코드:** 코드명이 고정적일 때 → 예) `남녀구분코드`
- **종류코드:** 지속적으로 늘어나는 코드명 → 예) `서비스종류코드`
- **유형코드:** 유사한 성질끼리 묶을 때 → 예) `거래유형코드`

**금액 도메인 특수 규칙 (기간/계산 수식어):**  
`기간수식어 + 주체 + 대상 + 행위 + 계산수식어 + 금액`

예) `연간고객주문합계금액`, `전월신용카드사용합계금액`, `최근6개월상품주문총금액`

**SQLite 메타 근거 (STD_DIC / STD_DOM):**  
- `STD_DIC`: `DIC_LOG_NM`(논리명)·`DIC_PHY_NM`(물리명)으로 표준 단어 조회·검증  
- `STD_DOM`: `KEY_DOM_NM`·`DATA_TYPE_CD`·`DATA_LEN`·`DATA_SCALE`·`DATA_FORMAT`으로 속성 도메인 결정  
- `STD_WORD_COMBI`: `ORDER_NO`(단어 순서)로 표준 용어 구성 단어 순서 관리  
- `STD_DATATYPE`: `DB_TYPE`별(`0001`=Oracle, `0002`=DB2 등) 물리 데이터타입 매핑

## ③ 단계별 업무계획

### Phase 0: 선행 조건 확인 (표준 단어/도메인 확보)

| 항목 | 내용 |
|---|---|
| **단계명** | 표준 단어·도메인·용어 가용성 확인 |
| **산출물** | 사용 가능 표준 단어 목록, 사용 가능 표준 도메인 목록 |
| **선행조건** | 10-standard 팀이 기초 표준 단어사전·도메인 등록 완료 |
| **DA활용DB** | `STD_DIC` (표준단어 조회), `STD_DOM` (표준도메인 조회), `STD_AREA` (주제영역 현황) |
| **소요기간** | 0.5일 |

**주요 활동:**
- `STD_DIC` 에서 업무 관련 표준 단어 검색 (`DIC_LOG_NM`, `STANDARD_YN='Y'`, `FORBID_YN='N'`)
- `STD_DOM` 에서 도메인 그룹 목록 확인 (`DOM_TYPE_CD`, `DATA_TYPE_CD`, `DATA_LEN`)
- 미등록 단어 식별 → Phase 3(표준 용어 신청) 대상 목록 작성

---

### Phase 1: 주제영역 정의

| 항목 | 내용 |
|---|---|
| **단계명** | 주제영역 계층 구조 정의 (1레벨 / 2레벨) |
| **산출물** | 주제영역 정의서 (주제영역명, 영문약어, 설명) |
| **선행조건** | 업무 범위 확정, `STD_AREA` 기존 등록 현황 파악 |
| **DA활용DB** | `STD_AREA` (STD_AREA_ID, STD_AREA_NM, UP_STD_AREA_ID, AVAL_ST_DT) |
| **소요기간** | 1일 |

**명명규칙 준수사항 (명명규칙-주제영역.pptx 기반):**
- 주제영역 계층은 최대 2레벨로 제한
- 명칭은 단수형 명사 사용
- 영문 약어: `시스템(1자) + 1레벨(2자) + 2레벨(1자)` = 4자리
- `UP_STD_AREA_ID`로 상·하위 관계 설정

---

### Phase 2: 논리 모델링

| 항목 | 내용 |
|---|---|
| **단계명** | 엔터티 정의 및 관계 설정 (논리 ERD) |
| **산출물** | 논리 ERD (엔터티·관계·속성·식별자 포함) |
| **선행조건** | Phase 1 주제영역 확정, Phase 0 표준 단어 가용성 확인 |
| **DA활용DB** | `STD_DIC` (속성명 구성 단어 조회), `STD_AREA` (주제영역 참조) |
| **소요기간** | 3~5일 |

**엔터티 명명규칙 준수사항 (명명규칙-엔터티.pptx 기반):**
- 엔터티명 = `[사용용도] + 주제영역명 _ 엔터티정의 + [데이터성격]`
- 2레벨 주제영역이 명확하지 않을 경우 1레벨만 사용 가능
- 집계 엔터티에는 반드시 `집계` 접미어 사용
- 이력 엔터티에는 반드시 `이력` 접미어 사용

**속성 명명규칙 준수사항 (명명규칙-속성.pptx 기반):**
- 최소 표준 단어 2개 이상 조합
- 수식어(주체+대상+행위) + 분류어(표준 도메인) 구조 준수
- `STD_DIC.FORBID_YN='Y'` 단어 사용 금지

---

### Phase 3: 표준 용어 신청

| 항목 | 내용 |
|---|---|
| **단계명** | 미등록 단어·도메인·표준 용어 신청 |
| **산출물** | 표준 용어 신청 목록 (논리명, 물리명, 도메인, 근거) |
| **선행조건** | Phase 2 논리 모델 초안 완성, `STD_DIC` 미등록 단어 식별 |
| **DA활용DB** | `STD_DIC` (기존 단어 중복 확인), `STD_DOM` (도메인 존재 여부 확인), `STD_WORD_COMBI` (단어 순서 확인) |
| **소요기간** | 1~2일 |

**주요 활동:**
- Phase 2에서 사용한 단어 중 `STD_DIC`에 미등록인 것 식별
- 10-standard 팀에 표준 단어 신청 요청 (논리명·물리명·약어·도메인 포함)
- 승인 후 `STD_WORD_COMBI`에 단어 조합 순서 등록 확인
- 물리명 변환 규칙: `STD_DIC.DIC_PHY_NM` 기준

---

### Phase 4: 물리 모델링

| 항목 | 내용 |
|---|---|
| **단계명** | 테이블·컬럼·키·인덱스 설계 (물리 ERD) |
| **산출물** | 물리 ERD, 데이터 타입 정의서, DDL 스크립트 |
| **선행조건** | Phase 2 논리 모델 확정, Phase 3 표준 용어 신청 완료 |
| **DA활용DB** | `STD_DATATYPE` (DB 타입별 데이터타입 매핑), `STD_DATATYPE_CONV` (DB간 타입 변환), `STD_DOM` (컬럼 데이터 길이·스케일) |
| **소요기간** | 2~3일 |

**데이터타입 결정 기준 (STD_DATATYPE 기반):**

| DB_TYPE | DB명 | 예시 데이터타입 |
|---|---|---|
| `0001` | Oracle | CHAR, NCHAR, VARCHAR2, NUMBER, DATE |
| `0002` | DB2 | CHAR, VARCHAR, DECIMAL, DATE |

- 속성 도메인의 `STD_DOM.DATA_TYPE_CD` + `DATA_LEN` + `DATA_SCALE`로 컬럼 타입 결정
- `LEN_YN='Y'`인 타입만 길이 지정
- `STD_DATATYPE_CONV`로 다중 DBMS 환경 타입 변환 매핑 관리

### Phase 5: DA샵 연동 Export

| 항목 | 내용 |
|---|---|
| **단계명** | DA샵 import용 CSV 파일 생성 |
| **산출물** | `dah_entity.csv`, `dah_attribute.csv`, `dah_word_dict.csv` |
| **선행조건** | Phase 4 물리 모델 확정, DA샵 import 형식 확인 |
| **DA활용DB** | `STD_DIC`, `STD_DOM`, `STD_AREA` (export 매핑 참조) |
| **소요기간** | 0.5~1일 |

**CSV 파일 설계 방향 (템플릿 빈 파일 → 헤더 설계 필요):**

`dah_entity.csv` 헤더 (설계안):
```
SUBJECT_AREA_NM,ENTITY_NM,ENTITY_PHY_NM,ENTITY_TYPE,ENTITY_DESC,USAGE_TYPE
```

`dah_attribute.csv` 헤더 (설계안):
```
ENTITY_NM,ATTR_NM,ATTR_PHY_NM,DOMAIN_NM,DATA_TYPE,DATA_LEN,DATA_SCALE,PK_YN,NULL_YN,ATTR_DESC
```

`dah_word_dict.csv` 헤더 (설계안):
```
WORD_LOG_NM,WORD_PHY_NM,WORD_ABBR,DOMAIN_NM,STANDARD_YN,FORBID_YN,WORD_DESC
```

## ④ 타 팀원과의 인터페이스

```
[00-리더] ◄──── 모델 초안·중간보고·최종 승인 요청 ────► [20-모델러]
                                                              │
[10-표준] ◄──── 표준 단어/도메인/용어 신청 & 조회 ──────────┤
                표준 단어사전(STD_DIC) 변경 사항 수신          │
                                                              │
[30-품질] ◄──── 모델 감리 수검 → 시정 조치 결과 제출 ────────┤
                                                              │
[40-이관] ◄──── 확정 물리 모델 제공 ─────────────────────────┘
                (이관 매핑 설계 입력 자료)
```

## ⑥ 참고 메타 구조 요약

```sql
-- 주제영역 조회
SELECT STD_AREA_ID, STD_AREA_NM, UP_STD_AREA_ID
FROM   STD_AREA
WHERE  AVAL_END_DT IS NULL
ORDER BY UP_STD_AREA_ID NULLS FIRST;

-- 속성명 구성 단어 조회 (표준단어 검색)
SELECT DIC_LOG_NM, DIC_PHY_NM, STANDARD_YN, FORBID_YN, DOM_ID
FROM   STD_DIC
WHERE  STANDARD_YN = 'Y' AND FORBID_YN = 'N'
  AND  DIC_LOG_NM LIKE '%고객%';

-- 도메인 조회
SELECT KEY_DOM_NM, DOM_TYPE_CD, DATA_TYPE_CD, DATA_LEN, DATA_SCALE, DATA_FORMAT
FROM   STD_DOM
WHERE  DOM_TYPE_CD = '기본';

-- Oracle 데이터타입 조회
SELECT DATA_TYPE, LEN_YN
FROM   STD_DATATYPE
WHERE  DB_TYPE = '0001';
```
