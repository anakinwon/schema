# 10. 데이터 표준 담당자 업무계획

## ① 역할 정의

데이터 표준 담당자는 **전사에서 사용할 수 있도록 표준화 지침을 만들고, 지침에 따른 표준 도메인과 표준 단어를 생성하며, 모델러가 신청한 표준 용어의 적절성을 검토하여 승인하는 역할**을 수행한다.

세부 역할은 다음 네 가지로 구분된다.

| 역할 ID | 역할명 | 주요 관리 대상 | DB 테이블 |
|---|---|---|---|
| 10-da-std-word-manager | 표준단어 관리자 | 표준단어 사전, 유사어(금칙어) 목록 | `STD_DIC` |
| 20-da-std-domain-manager | 표준도메인 관리자 | 기본 도메인, 도메인 그룹, 도메인 타입 | `STD_DOM`, `STD_DOM_GRP` |
| 30-da-std-term-manager | 표준용어 관리자 | 용어 사전, 단어 조합 | `DA_TERM`, `STD_WORD_COMBI` |
| 40-da-std-code-manager | 표준코드 관리자 | 공통 코드, 코드 인스턴스 | `STD_CODE` |

## ② 참고한 지침서 및 근거

### 10.표준단어_지침서 — 핵심 원칙

**단어 정의 방식 (§3.1)**
> "표준 단어는 업무상 사용하는, 일정한 의미를 갖고 있는 최소 단위의 단어를 의미하며 표준 용어에 사용된다."
> "표준 단어를 정의하기 위해서는 단어 명, 영문 명(Full Name), 영문 약어 명, 단어 설명 등이 필요하다."

예시 (지침서 원문 인용):

| 단어 명 | 영문 명 | 영문 약어 명 | 단어 설명 |
|---|---|---|---|
| 고객 | Customer | CT | 서비스를 이용하는 사람 |
| 부가가치세 | Value Added Tax | VAT | 부가가치에 과세하는 간접세 |

**단어 구분 체계 (§3.2)**
> "단어는 표준 관점에 따라 표준어와 유사어로 구분할 수 있다. 이음동의어가 존재할 때 대표 단어 하나만 표준어가 되며, 나머지는 유사어가 된다."
> "단어는 용어에서 수행하는 역할에 따라 기본어와 분류어로 구분할 수 있다. 분류어는 표준 도메인에 해당된다."

**기본 원칙 (§3.3) — 주요 금칙 규정**
- 이음동의어(Synonym) 허용 금지: "이음동의어를 허용하면 같은 의미인데 여러 개의 표준 용어가 생성될 수 있기 때문에 이음동의어는 허용하지 않는다."
- 특수 문자 금지: "표준 단어에 특수 문자(`/`, `&`, `_`, `-`)는 사용하지 않는다." (단, DA 승인 시 `S&P`, `L/C` 같은 고유명사 예외)
- 외래어 한글화 원칙: "표준 단어에는 가능한 영문 단어를 사용하지 않고, 의미를 파악할 수 있도록 한글화하는 것을 원칙으로 한다."
- 영문 두문자어: "관용적으로 사용하는 영문 두문자어(Acronyms)의 경우, 한글 단어는 유사어로 정의한다."

유사어(금칙어) 등록 실제 사례 (지침서 원문):

| 유사어 (금칙어) | 표준어 |
|---|---|
| 갱신 | 수정 |
| 구좌 | 계좌 |
| 직원, 행원 | 사원 |
| 주민번호 | 주민등록번호 |

### 20.표준도메인_지침서 — 핵심 원칙

**도메인 정의 (§4.1)**
> "속성의 데이터 성격을 분류한 것으로서 도메인은 데이터의 타입(숫자, 문자, 날짜 등의 분류) 및 값의 범위나 길이 등의 분류를 정형화한 것으로 데이터 유효성을 정의하고 통제하는 데 중요한 요소이다."
> "동일한 표준 도메인을 사용하고 있는 속성에 대해서는 데이터 타입/길이를 동일하게 유지할 수 있도록 모든 속성에는 도메인이 반드시 지정돼야 한다."

**도메인 그룹 체계 (§4.2) — 지침서 원문 인용**

| 도메인 그룹 명 | 약어 | 의미 |
|---|---|---|
| 금액 | A (Amount) | 금전적 수치 |
| 내용 | T (Text) | 텍스트 정보 |
| 번호 | N (Number) | 식별 번호 |
| 날짜 | D (Date) | 날짜/일시 정보 |
| 코드 | C (Code) | 코드 값 |
| 여부 | F (Flag) | Y/N 플래그 |
| 수 | N (Number) | 수량 |
| 값 | V (Value) | 일반 수치 |
| 명 | N (Name) | 이름/명칭 |
| 율 | R (Rate) | 비율 |

**도메인 타입 명명 규칙 (§4.2)**
> "도메인 타입 명은 '도메인그룹 명+데이터타입분류(2)+자릿수[+`.`+SCALE]'로 정한다."

도메인 타입 사례 (지침서 원문):

| 도메인 타입 명 | 도메인 그룹 |
|---|---|
| 금액 NB21.3 | 금액 |
| 번호 VC13 | 번호 |
| 내용 VC1000 | 내용 |
| 여부 VC1 | 여부 |
| 날짜 DT | 날짜 |

**데이터 타입 분류 (지침서 원문)**

| 분류 코드 | 데이터 타입 |
|---|---|
| CH | Char |
| VC | Varchar |
| NB | Number |
| DT | Date |
| TS | Timestamptz |
| CL | Clob |
| BL | Blob |

> "데이터 타입은 문자형의 경우 CHAR 타입은 사용하지 않고 VARCHAR 타입으로 일원화하여 사용하며, 길이는 다국어가 가능하도록 한글 한 글자를 3Bytes로 설계한다."

**여부 도메인 원칙 (§4.3)**
> "여부 도메인에 대한 유효한 값은 'Y'와 'N'만을 사용한다. 다만 '해당없음(0)', '모름(9)'을 관리해야 하는 경우에는 '0'과 '9' 값을 사용한다."

### 30.표준용어_지침서 — 핵심 원칙

**용어 정의 (§5.1)**
> "표준 용어는 000㈜에서 사용하는 용어로 의미가 동일한 용어에 대한 통일되고 표준화된 용어를 의미하며, 표준 단어와 표준 도메인의 조합으로 구성된, 업무 의미를 지니는 용어로서 엔터티의 속성에 사용된다. 즉 표준 용어는 속성을 의미한다."

용어 구성 예시 (지침서 원문):

| 용어명 | 용어영문명 | 도메인 타입 | 용어설명 |
|---|---|---|---|
| 이체서비스신청일자 | TF_SV_RQ_DT | 일자 DT | 이체 서비스를 신청한 일자 |
| 고객자택전화번호 | CT_HS_TN | 번호 VC20 | 고객의 자택 전화번호 |

**용어 구성 원칙 (§5.3)**
> "표준 용어는 최소한 한 개 이상의 표준 단어의 조합으로 '수식어(표준 단어)+도메인(표준 도메인)' 형태로 구성한다."
> "표준 용어에는 구분자('_')나 띄어쓰기 없이 붙여 정의하며, 가독성을 위해 최대 길이를 20자로 제한한다."

**용어 영문명 생성 원칙 (§5.1)**
> "표준 용어 영문 명은 표준 용어 명으로 구성된 표준 단어들의 영문 약어 명을 구분자('_')로 구분하여 생성된다."
> "표준 용어 영문 명은 메타 시스템에서 자동으로 생성하며, 최종적으로 테이블의 컬럼 명으로 사용한다."

**금칙 용어 원칙 (§5.4 — 지침서 원문)**

| 금칙 용어 패턴 | 대체 표준 용어 |
|---|---|
| 수수료+금액, 수수+금액 | 수수료 |
| 상태구분코드 (일반적 표현) | 주문상태구분코드 |
| 주문자번호 | 주문회원번호 |
| 누적금액 (수식어 1개) | 주문누적금액 |

### 40.표준코드_지침서 — 핵심 원칙

**코드 정의 (§6.1)**
> "표준 코드는 000㈜에서 사용하고 있는 공통 코드를 의미하며, 코드 체계 등의 표준 체계와 세부 지침을 수립하여 전사에서 공통으로 사용할 수 있도록 배포하고 검토, 통제하여 표준 코드의 정합성과 활용성을 높인다."
> "'01', '02', '03' 등과 같이 의미가 없는 번호를 '코드값'이라고 하며, 코드 값에 대한 의미를 나타내는 명을 '코드 값 명'이라고 한다."

**코드 관리 방안 (§6.2)**
> "업무적으로 동일한 의미의 코드는 통합하여 표준으로 정의하여, 동일한 내용의 코드를 사용 형태나 업무 범위에 따라 중복 정의하여 사용하지 않는다."
> "모든 표준 코드는 관리 부서에 해당하는 오너십을 부여하여 관리한다."

**코드 유형 구분 (§6.4 — 지침서 원문)**

| 구분 | 설명 | 예시 |
|---|---|---|
| 공통 코드 (통합 코드) | 코드 값과 코드 값 명을 메타 시스템에서 관리 | 고객유형코드 01:개인, 02:법인 |
| 개별 코드 (식별 코드) | 개별 엔터티에서 식별자 역할 | 기관.기관코드, 부서.부서코드 |

**코드 구분자 원칙 (§6.5 — 지침서 원문)**

| 구분자 | 설명 | 예시 |
|---|---|---|
| 유형코드 | 공통의 성질로 묶은 집합 | 고객유형코드 |
| 구분코드 | 상호 배타적이고 더 이상 늘어나지 않는 경우 | 매수매도구분코드 |
| 종류코드 | 지속적으로 늘어날 수 있는 경우 | 거래매체종류코드 |

### 명명규칙 pptx — 핵심 명명 규칙

**주제 영역 명명 규칙 (명명규칙-주제영역.pptx)**
> "주제 영역 명은 업무를 설명하는 단수형 명사를 사용한다."
> 구조: `시스템 명 + _ + 1레벨 주제영역 명 + / + 2레벨 주제영역 명`

예) `업무_고객/기본`, `DW_계약/조건`

주제 영역 영문 약어 체계: `시스템영문(1자리) + 1레벨주제영역영문(2자리) + 2레벨주제영역영문(1자리)` → 4자리 약어

**엔터티 명명 규칙 (명명규칙-엔터티.pptx)**
> 구조: `[사용 용도] + 주제 영역 명 + _ + 엔터티 정의 + [데이터 성격]`

- 엔터티 정의는 주체(~이), 대상(~를), 행위(~한) 요소로 구성
- 데이터 성격 접미어: `이력`, `집계`, `백업`, `복제`, `인터페이스`, `채번`, `코드`

예) `고객/기본_고객`, `고객/기본_고객등급이력`, `고객/기본_주문집계`

**속성 명명 규칙 (명명규칙-속성.pptx)**
> "표준 용어는 최소한 두 개 이상의 표준 단어의 조합으로 사용 (속성 도메인 등 예외 존재)"
> 구조: `수식어(표준 단어) + 분류어(표준 도메인)`

- 코드 속성 명: `수식어 + 구분자 + 코드`
- 구분자는 `유형코드`, `구분코드`, `종류코드` 세 가지로 한정

### Phase 1: 표준화 지침 수립

| 항목 | 내용 |
|---|---|
| **단계명** | 표준화 지침 수립 및 DA 리더 승인 |

| **주요 활동** | 기존 4개 지침서(10/20/30/40) 현행화 검토, 명명규칙 pptx 업데이트, 금칙어 초안 작성, DA 리더 검토 및 승인 |

### Phase 2: 표준 단어 구축

| 항목 | 내용 |
|---|---|
| **단계명** | 표준단어 사전 구축 및 금칙어 등록 |
| **산출물** | STD_DIC 등록 완료, 금칙어(유사어) 목록 |
| **선행조건** | Phase 1 완료 (지침서 승인) |
| **DB 테이블** | `STD_DIC`, `STD_DIC_REL` |
| **소요기간** | 2주 |
| **주요 활동** | 기본어/분류어 구분 후 등록, 이음동의어(Synonym) 식별 및 유사어 처리, 영문 약어 명 부여, 금칙어 목록 확정 |

**STD_DIC 등록 기준 (지침서 §3.1 기반)**
- `DIC_LOG_NM`: 한글 단어 명 (띄어쓰기 없음)
- `DIC_PHY_NM`: 영문 약어 명 (대문자, 특수문자 제외)
- `DIC_PHY_FLL_NM`: 영문 전체 명 (Full Name)
- `FORBID_YN`: 금칙(유사어) 여부 (`Y`/`N`)
- `ENT_CLSS_YN`: 엔터티 분류어 여부
- `ATTR_CLSS_YN`: 속성 분류어 여부 (도메인 단어인 경우 `Y`)

### Phase 3: 표준 도메인 구축

| 항목 | 내용 |
|---|---|
| **단계명** | 도메인 그룹 및 기본 도메인 구축 |
| **산출물** | STD_DOM 등록 완료, STD_DOM_GRP 등록 완료 |
| **선행조건** | Phase 2 완료 (분류어 단어 등록) |
| **DB 테이블** | `STD_DOM`, `STD_DOM_GRP` |
| **소요기간** | 1주 |
| **주요 활동** | 도메인 그룹 10종 확정 (금액/내용/번호/날짜/코드/여부/수/값/명/율), 도메인 타입 정의 (`도메인그룹명+데이터타입분류(2)+자릿수`), 여부 도메인 유효값(`Y/N`) 확정, DBMS별 도메인 타입 매핑 |

**STD_DOM 등록 기준 (지침서 §4.2 기반)**
- `KEY_DOM_NM`: 핵심 도메인 명 (예: 금액, 번호)
- `DOM_NM`: 도메인 명 (예: 금액NB21.3)
- `DOM_TYPE_CD`: 도메인 유형 코드
- `DATA_TYPE_CD`: 데이터 타입 코드 (CH/VC/NB/DT/TS/CL/BL)
- `DATA_LEN`: 데이터 길이
- `DOM_GRP_ID`: 도메인 그룹 ID (STD_DOM_GRP 참조)
- `DIC_ID`: 연결 단어 ID (STD_DIC 참조)

| **산출물** | DA_TERM 등록 완료, STD_WORD_COMBI 등록 완료 |
| **선행조건** | Phase 2, Phase 3 완료 |
| **DB 테이블** | `DA_TERM`, `STD_WORD_COMBI` |
| **소요기간** | 2주 |
| **주요 활동** | 핵심 업무 속성 용어 초안 수집, 용어 명 = `수식어(표준단어)+도메인(표준도메인)` 형태 검증, 영문 약어 명 자동 생성 확인(구분자 `_`), 최대 20자 제한 준수, 금칙 용어 식별 및 유사어 등록 |

**DA_TERM 등록 기준 (지침서 §5.1 기반)**
- `TERM_NM`: 용어 명 (구분자 없음, 최대 20자)
- `TERM_GBN_CD`: 용어 구분 코드 (일반속성/도메인속성/코드속성)
- `TERM_ABBR`: 영문 약어 명 (최대 28자, 가능한 20자 이내)
- `LANG_CD`: 언어 코드

**STD_WORD_COMBI 등록 기준**
- `TERM_ID`: 용어 ID
- `ORDER_NO`: 단어 구성 순번
- `WORD_ID`: 단어 ID (STD_DIC 참조)

| **소요기간** | 2주 |
| **주요 활동** | 기존 코드 목록 수집 및 중복 통합, 내부/외부 코드 구분, 오너십 부서 지정, 공통/개별 코드 판별, 계층/참조 코드 체계 정의, 코드 구분자(`유형코드`/`구분코드`/`종류코드`) 적용 |

- `CD_LEN`: 코드 길이
- `UP_CD_ID`: 상위 코드 ID (계층/참조 코드용)

### Phase 6: 신청·검토·승인 운영

| 항목 | 내용 |
|---|---|
| **단계명** | 표준 용어 신청·검토·승인 프로세스 운영 |
| **산출물** | 신청·승인 절차서, 처리 이력 |
| **선행조건** | Phase 2~5 완료 (기초 표준 구축) |
| **DB 테이블** | `DA_TERM`, `STD_DIC`, `STD_DOM`, `STD_CODE` |
| **소요기간** | 상시 운영 |
| **주요 활동** | 모델러의 표준 용어 신청 접수, 표준 단어/도메인 존재 여부 확인, 명명 규칙 준수 여부 검토, 중복 용어 여부 확인, 승인 또는 반려(사유 명기), 승인 후 메타 시스템 등록 |

**처리 절차 (지침서 §5.4 기반 원칙 적용)**
1. 신청 용어가 표준 단어 조합으로 구성됐는지 확인 (`STD_DIC` 조회)
2. 용어 구성이 `수식어+도메인` 형태를 준수하는지 확인 (`STD_DOM` 조회)
3. 금칙 패턴 해당 여부 확인 (지침서 §5.4 금칙 목록 대조)
4. 이음동의어 존재 여부 확인 (`DA_TERM` 중복 조회)
5. 승인: `DA_TERM` 등록 + `STD_WORD_COMBI` 구성요소 등록
6. 반려: 사유 코멘트 기재 후 모델러에게 재신청 요청

## ⑥ 단계별 선후행 요약

```
Phase 1 (지침 수립)
    ↓ DA 리더 승인
Phase 2 (표준단어 구축)
    ↓ 분류어 단어 등록 완료
Phase 3 (표준도메인 구축)
    ↓ STD_DOM 등록 완료
Phase 4 (표준용어 구축)
    ↓ 코드 속성 용어 등록 완료
Phase 5 (표준코드 구축)
    ↓ 기초 표준 구축 완료
Phase 6 (신청·승인 운영) ← 상시 운영
```

> **참고**: Phase 2와 Phase 3은 병행 가능하나, Phase 3의 `STD_DOM`에 연결되는 분류어 단어는 Phase 2에서 `STD_DIC`에 먼저 등록돼야 한다 (`DOM_ID ↔ DIC_ID` FK 관계).
